### 40.153 (Primary gateway) deep-dive

- `rtmpgcp`'s SDI branch E_FAIL (`Failed to schedule frame 0x80000008`) burns card frames on every start (`Ran out of free frames` +2 per run); on a shared whole-card pool this wedged sibling routes. ### `.7` — Graceful shutdown + reconnect backoff
- `lib/blackgate/helpers.ex`: `sys_kill` now sends SIGTERM by default; new `sys_kill9` for escalation.
- `lib/blackgate/route_handler.ex`: `close_port` sends SIGTERM then arms a 5 s `{:escalate_kill, port, pid}` force-kill check; failed reconnect attempts back off exponentially (10 s → cap 120 s) at both re-arm sites; intentional 250 ms switches unchanged.
- `native/src/main.c`: `g_unix_signal_add(SIGTERM/SIGINT)` (glib-unix.h — `gio/gunixsignal.h` does not exist on glib 2.80) → prints `Termination signal received, shutting down pipeline` and quits the main loop, so `cleanup_pipeline` returns DeckLink scheduled frames instead of orphaning them. Pre-init window still default-dies (accepted).
- Standalone proof: SIGTERM → graceful line + clean same-second exit; SIGKILL control → no graceful path. This converts the `.5`-era death spiral (kill -9 → frames never returned → card pool exhausted → permanent black) into a ≤70 s self-heal. Field-proven on 40.153: a startup wedge self-recovered after exactly one watchdog restart.

### A/B/C source experiment — the card is guilty, not the sources
- Matrix (standalone binary, dev7, GST_DEBUG `decklink*:6`, dmesg deltas): **A** OBS 10049 (after operator changed OBS latency) PASS; **B** MediaMTX 40.72:8890 FAIL — 2× E_FAIL at wall 6.708 s / 13.41 s; **C** production 50.152:17001 PASS.
- Forensics: E_FAIL lands on exactly the **65th/66th prepared frame**; 65 = BlackmagicIO driver free-frame pool size; after the first E_FAIL the video branch wedged retrying the same pts while audio advanced. RAW mux audio-leads-video skew exists in ALL three sources (+2.0…+5.3 s) and does NOT separate pass/fail.
- Decisive no-card control: the exact B stream decoded 659 frames at 25.3 fps for the full window with NO DeckLink in the path → source/demux/decode clean; the card/driver refuses to schedule when ~65 frames (2.6 s) sit outstanding.

## Key Decisions & System Constraints Resolved

- E_FAIL root cause: driver 65-frame hardware pool exhausts when video is scheduled ~2.6 s ahead (mux A/V skew + warm-up backlog). Fix belongs at the sink pacing layer (`.8`), not in per-source workarounds.
- Pacing invariant (new): `decklinkvideosink sync=TRUE` owns pacing; the pre-sink `identity` must stay `sync=FALSE`.
- Graceful-shutdown invariant: pipelines are always SIGTERM'd first; `kill -9` only after a 5 s escalate — because SIGKILL orphans scheduled DeckLink frames and exhausts the card pool.
- `native/AGENTS.md` still documents the OLD sync invariant; needs a one-line update to match `.8` (pending).
- The OBS source class stopped reproducing after the operator raised OBS-side latency — keep sources with sane latency, but blackgate no longer depends on it.
