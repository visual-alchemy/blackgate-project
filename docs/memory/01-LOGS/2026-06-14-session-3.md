# Session Log: 2026-06-14 - Session 3

## Sprint Goal & Focus
Diagnose and fix the live preview showing "Waiting for client..." persistently, even when routes are running.

## Root Cause Identified

The `StatsChannel.join/3` function was calling `push/3` directly inside the `join/3` callback — a runtime violation in Phoenix 1.7+. This caused every `route:stats:*` channel join to crash with:

```
(RuntimeError) push/3, reply/2, and broadcast/3 can only be called after the socket has finished joining.
```

Since all Phoenix channels on a given WebSocket share the same transport process, the crash terminated the **entire WebSocket connection**, which also killed all `preview:*` channels immediately after they joined (logged as `{:shutdown, :left}`). This is why the "Waiting for client..." overlay never cleared — the preview channels connected, received data, and then were torn down before any video frames could be flushed to JMuxer.

## What Was Accomplished

### 1. Fixed `stats_channel.ex`
* **Removed** the direct `push/3` call from inside `join/3`.
* **Added** `send(self(), :after_join)` to schedule an immediate deferred push.
* **Added** a new `handle_info(:after_join, socket)` clause that safely calls `push/3` after the join handshake completes — preserving the "send last cached stats on join" behavior without crashing.

### 2. Deployed to Remote Gateway
* **SCP'd** the fixed `stats_channel.ex` to the remote gateway.
* **Rebuilt** the OTP release (`MIX_ENV=prod mix release --overwrite`).
* **Restarted** the `blackgate` systemd service.

### 3. Verified Fix
Confirmed via `journalctl` that:
* All 3 `route:stats:*` channels `JOINED` without any `RuntimeError`.
* All 3 `preview:*` channels `JOINED` and connected to their respective GStreamer TCP ports (40084, 40537, 40861).
* No `{:shutdown, :left}` disconnections after joining.
* Zero `push/3` violation errors in logs.

## Key Decisions & System Constraints Resolved
* **Phoenix Channel Push Rule:** `push/3` must never be called directly inside `join/3`. Always defer via `send(self(), :after_join)` and handle in `handle_info/2`.
* **WebSocket Transport Sharing:** All Phoenix channels on one WebSocket share the transport. A crash in one channel kills all others — the stats channel crash was the single point of failure for the entire preview system.
