## What Was Accomplished

### Full Session Arc (Sessions 1–5, 2026-06-14)

**Problem investigated:** Dashboard Live Preview cards showed "Waiting for client…" perpetually even though routes were active and GStreamer pipelines were running.

**Root causes found and fixed (in order):**

1. **`stats_channel.ex` push-in-join crash** — `push/3` called directly inside `join/3`, crashing the entire WebSocket transport and killing all preview channels via `{:shutdown, :left}`. Fixed with `send(self(), :after_join)` deferred push pattern. *This fix was manually deployed to the remote but never committed to git — it was lost during the rollback.*

2. **GStreamer preview branch sending raw MPEG-TS** — JMuxer expects H.264 Annex-B NAL units. Added `tsdemux → h264parse (byte-stream) → tcpserversink` with dynamic pad callback. *Worked correctly but caused CPU spike.*

3. **Dashboard self-refresh every 30s** — `setLoading(true)` in the 30-second poll interval caused the entire Live Preview card to blank out. Fixed with `isFirstLoad` ref.

4. **MSE SourceBuffer memory growth** — JMuxer never evicts old video data. Added a 20-second watchdog that reinitialises JMuxer when buffered video > 45 seconds.

**Why the live preview was rolled back:**
- BEAM CPU: **12.9%** sustained with 3 active routes and live preview open.
- Cause: PreviewChannel encoding ~75 H.264 NAL units/sec as Base64 + JSON + WebSocket frames on the BEAM.
- Decision: revert to last GitHub commit, keep the dashboard stable.

**After rollback:**
- BEAM CPU: **0.0–4.9%** with 3 routes running (normal baseline).
- All 3 GStreamer pipelines running at 8.3%, 5.7%, 3.8% CPU (stream processing only).

## Key Decisions & System Constraints

- **Live preview via WebSocket is too expensive on the BEAM.** Base64 + Jason + Phoenix WebSocket framing at 25fps/route per connected client is not viable for the current architecture.
- **JPEG thumbnail approach** (already built — `/tmp/blackgate_preview_*.jpg` via GStreamer appsink) is the low-CPU alternative. Polling at 2–4 fps would cost near-zero BEAM overhead.
- **HLS fMP4 segments** would also work — GStreamer segments the video, Elixir serves files via HTTP range requests — but requires segment muxing pipeline.
- **The `stats_channel.ex` `:after_join` bug is still unpatched in git.** It was deployed to remote manually but is NOT in `326b397`. Next session should commit this fix properly before other work.
