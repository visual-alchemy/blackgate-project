### True SDI Auto-Detect Implementation (commit `bfeff67`)

**Native C Pipeline (`gst_pipeline.c`):**
- Added `DeckLinkModeEntry` struct and static lookup table of 15 broadcast-standard modes (1080p/i, 720p, PAL/NTSC SD, 4K UHD).
- Added `lookup_decklink_mode()` function for caps-to-mode mapping.
- Added `SdiAutoDetectCtx` context struct for deferred video chain linking.
- Added `on_sdi_decodebin_video_pad_added_autodetect()` callback — the core of the feature:
  - Extracts decoded video caps (`width`, `height`, `framerate`, `interlace-mode`) from decodebin.
  - Normalizes NTSC fractional rates (`30000/1001` → `30/1`).
  - Looks up matching DeckLink mode; falls back to `1080p25` if no match.
  - Configures `decklinkvideosink` mode, capsfilter caps, optionally adds `interlace` element.
  - Links full video chain and starts flow.
- Added `sdi_detected_mode[8]` global for stats — detected mode included in SDI stats JSON.
- Modified `add_sink_to_pipeline()` with two paths:
  - **Auto path:** Video chain deferred, callback handles everything at runtime.

## Key Decisions & System Constraints
- **Deferred linking approach** (not dynamic reconfiguration): The video chain stays unlinked until `decodebin` delivers the first decoded frame. This avoids risky `PLAYING → READY → PLAYING` state transitions on the DeckLink sink that could cause glitches.
- **Auto-detect is opt-in**: Available as a dropdown option but not the default, since broadcast operators usually know their source format.
- **Fallback safety**: If auto-detect can't match (e.g., non-standard webcam resolution), it falls back to `1080p25` and uses `videoscale`/`videorate` for conversion.
