# 2026-10-17 Session 1 — Fresh-Host Install, SRT Route Bring-Up, Telemetry and OS Stats Fixes

## Sprint Goal & Focus

Make `make install` work on a fresh Ubuntu host, get a real SRT route running on
the Rust engine, and fix the telemetry and system-stats defects found while
verifying it.

## What Was Accomplished

### Toolchain / install path

- `scripts/bootstrap_pinned_tools.sh` (new): installs Erlang/OTP 27.0.1, Elixir
  1.18.2, Node 20.19.0 and Rust 1.96.0 from sha256-pinned upstream tarballs into
  `~/.blackgate/toolchain`, builds a `bin/` symlink farm so `#!/usr/bin/env
  elixir` resolves without rc files, and records PATH + `ERL_ROOT` in both
  `.bashrc` and `.profile` (login shells). Skips any tool already on PATH at the
  exact pinned version, so brew/asdf installs are untouched.
- `Makefile`: `install` rewritten as six steps in one shell with `@set -e;`
  (the missing `@` made make echo the whole recipe instead of its output), added
  `ripgrep ca-certificates xz-utils unzip libncurses6 libssl3t64` to the apt list,
  and exported the toolchain PATH/`ERL_ROOT` at Makefile scope so `make build`,
  `make start` and `make dev-all` work in non-interactive shells.
- Guard scripts no longer require ripgrep: `scripts/check_toolchain_contract.sh`,
  `scripts/check_rust_only_runtime.sh` and their self-tests now use POSIX `grep`
  (`grep -Fqx`, `grep -Eq`, `grep -rnE`). The old scripts called `rg`, which is
  only installed by step 2 — step 1 died with `rg: command not found` on a fresh
  host, and the follow-on "missing required value" errors were misleading.

### Rust engine

- `engine-gst/src/builder.rs`: element properties are now dispatched on
  `pspec.value_type()`. `pspec.type_()` returns the param-spec CLASS type
  (`GParamBoolean`), so every bool property fell through to an `i32` set and glib
  panicked — `property 'auto-reconnect' ... (expected: 'gboolean', got: 'gint')`
  — killing the engine at spawn. That was the whole reason a real SRT route was
  refused and reconnect-looped every 10s.
- `engine-stats/src/lib.rs`: the source byte counter was read from the struct key
  `total-bytes-received`, which is only the JSON wire key; the srtsrc struct field
  is `bytes-received-total`. The lookup returned 0 silently, so `bytes-received`
  (the control plane's "is data flowing?" fallback and the stall watchdog's input)
  was permanently 0. Also reads the element's own per-report `bytes-received` with
  the total delta as fallback, and parses the step is now testable
  (`apply_source_stats_structure`).
- `engine-stats/src/lib.rs`: each telemetry record is now written in ONE call
  (identical bytes to the previous prefix/payload/newline sends), so a socket
  chunk boundary cannot land between `stats_sink:` and its JSON.
- Regression tests added for both defects (33 workspace tests, up from 31).

### Control plane

- `unix_sock_handler.ex`: payloads arriving as `"\nstats_sink:{...}"` matched no
  clause and were dropped (54 occurrences) — leading newlines are now stripped and
  re-dispatched. An orphaned `stats_sink:` prefix is remembered so the next chunk
  is routed to the sink slot; previously that JSON matched the generic
  "starts with `{`" clause and overwrote the SOURCE stats slot, which made
  `health` flap to `disconnected` and the watchdog read the byte counter as 0.
- `route_handler.ex`: the stall watchdog treated only an INCREASE in the
  cumulative byte counter as activity, so a counter reset (engine restart, SRT
  session re-created) read as "no data" and killed a healthy pipeline 60s later.
  Any movement now counts and a reset re-baselines; same fix in the failover
  health path, and `:start` resets the baseline.
- `process_monitor.ex`: the Linux parsers returned `swap:`/`swap_bytes:` but no
  `swap_percent:` (darwin did), which failed two tests whenever a real engine
  process existed.
- `monitoring/os_mon.ex` + new `monitoring/cpu_sampler.ex`: RAM now uses
  `available_memory` (MemAvailable) instead of `free_memory`, and CPU is sampled
  from a long-lived GenServer instead of a per-request `:cpu_sup.util/0` call.

### Web

- `RouteStats.jsx`: added Retransmitted and Receive Latency tiles plus the
  per-caller fallback (ported from `feat/decklink-duo2`); caller-mode routes
  previously showed all-zero packet counters.

## Key Decisions & System Constraints Resolved

- `make install` needs root only for the apt step; toolchains are user-local and
  the script is sudo-free, which keeps it testable end to end.
- `scripts/sudoers.d/blackgate-dev` grants NOPASSWD for apt/apt-get/dpkg/
  add-apt-repository only, so `make install` runs unattended. It hardcodes the
  `dvls` user.
- The engine's telemetry protocol is PREFIX-delimited, not line-delimited: the
  handshake record `route_id:<id>` deliberately has no trailing newline, so full
  line-buffering in the reader would swallow the handshake. The reader therefore
  tolerates a dangling prefix instead.
- `Pipeline construction is invalid, please add queues` plus the paired
  `clock problem` are one condition, not two bugs: `gstbasesink.c` warns when a
  sync sink's processing deadline cannot fit the upstream latency window, clamps
  `min = max`, and `gstpipeline.c` then warns about `max < min`. srtsrc reports
  its configured latency as both bounds (`min == max == 2100ms`), so this is
  expected; queues already exist on every tee branch (`queue2` 50MB/3s on sink
  branches, `thumb-queue` on the thumbnail branch) and the sink configuration is
  byte-identical to blackgate-lite. Inherited, not a regression — left alone.
- `feat/decklink-duo2` has the SAME RAM bug and its `route_stats_registry` /
  `route_health` diffs are cosmetic only; its `OutputPopover` SDI port map belongs
  to that card's wiring and must not be ported.
- `web_app/yarn.lock` removed: `package-lock.json` is the canonical lockfile and
  `npm ci` rewrote the yarn file on every `make install`.
