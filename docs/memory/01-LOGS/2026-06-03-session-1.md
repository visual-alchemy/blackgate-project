# Session Log: 2026-06-03 - Session 1

## Sprint Goal & Focus
Brainstorm roadmap items for SDI output auto-detection, diagnose a multi-day SDI playout freeze, and resolve the issue where interlaced video modes (such as 1080i50) did not display output.

## What Was Accomplished
- **Roadmap Planning & Documentation (`SDI_FIXES.md`)**:
  - Outlined detailed design architectures for **True SDI Auto-Detect** (dynamic caps extraction via pad probes, lookup mapping in C, blocking/state reconfiguration, and fallback handling).
  - Outlined design criteria for **Audio Routing Configuration** (stream selection for multi-track feeds, channel mapping using `audiomixmatrix`, and UI integration).
  - Staged, committed, and pushed these documentation updates to GitHub.
- **SDI Freeze Diagnosis**:
  - Analyzed a GDB stack trace for a frozen C pipeline (`blackgate_pipeline`).
  - Identified that the GStreamer audio queue source thread was permanently blocked inside a kernel `ioctl` call within `libDeckLinkAPI.so` (LWP 809392). This confirmed a driver-level/hardware lockup of the DeckLink Quad 2 card under multi-day load, which froze upstream decoding.
  - Outlined recovery steps (stopping blackgate, force-killing orphaned GStreamer PIDs, and restarting the `DesktopVideoHelper` driver service).
- **Interlaced Mode Fix (`1080i50`)**:
  - Discovered that GStreamer's `decklinkvideosink` requires caps containing `interlace-mode=interleaved` when using interlaced modes like `1080i50` or `1080i60`. Without this, progressive negotiation occurs, causing the hardware output to fail or render black.
  - Modified [route_handler.ex](file:///Users/eldyreynanda/Developer/Antigravity/blackgate-project/lib/blackgate/route_handler.ex) to inspect the selected SDI video mode and append an `"interlaced"` boolean flag to the destination JSON options.
  - Modified [gst_pipeline.c](file:///Users/eldyreynanda/Developer/Antigravity/blackgate-project/native/src/gst_pipeline.c) to parse the `"interlaced"` JSON flag and dynamically append `", interlace-mode=interleaved"` to the GStreamer caps when active.
  - Verified local compilation (both Elixir and C) and successfully pushed the fixes to `origin/rtmp-ffmpeg`.

## Key Decisions & System Constraints Resolved
- **Interlaced Negotiation Compliance**: GStreamer requires explicit scan-type caps properties for physical interlaced sinks. Adding the dynamic `interlaced` property bridge ensures PAL `1080i50` and NTSC `1080i60` modes negotiate with correct scan layouts without breaking progressive formats like `1080p25` or `1080p50`.
