# Session Log: 2026-06-14 - Session 4

## Sprint Goal & Focus
Fix "Waiting for client..." live preview and dashboard refresh issues, then roll back the live preview feature due to unacceptable CPU cost.

## What Was Accomplished

### 1. Fixed StatsChannel push-in-join crash (deployed ✅)
* Identified `stats_channel.ex` calling `push/3` inside `join/3` — a runtime violation in Phoenix 1.7.
* Fixed by deferring the initial push via `send(self(), :after_join)` → `handle_info(:after_join)`.
* This was crashing the entire WebSocket transport for every dashboard client, causing all preview channels to immediately disconnect with `{:shutdown, :left}`.
* **This fix is still active in the rollback** — the `stats_channel.ex` change was committed to local but the remote was also patched separately.

### 2. Fixed GStreamer preview branch to send H.264 NAL units (local only, rolled back on remote)
* The original preview branch sent raw MPEG-TS over TCP. JMuxer expects H.264 Annex-B NAL units.
* Added `tsdemux → h264parse (byte-stream) → tcpserversink` pipeline with dynamic pad handling.

### 3. Fixed dashboard self-refresh every 30 seconds (local only, rolled back on remote)
* The `fetchStats` interval was calling `setLoading(true)` every 30 seconds, causing the entire Live Preview card to flash/hide momentarily.
* Fixed by tracking `isFirstLoad` ref — loading spinner only shows on initial mount.

### 4. Added MSE buffer watchdog (local only, rolled back on remote)
* JMuxer's MSE SourceBuffer never evicts old data — ~45 MB/min/route of browser RAM accumulation.
* Added a `setInterval` watchdog that destroys and reinitialises JMuxer when buffered video exceeds 45 seconds.

### 5. Rolled back remote gateway to last GitHub commit (deployed ✅)
* **Reason:** BEAM CPU at 12.9% with live preview active — caused by PreviewChannel Base64-encoding and WebSocket-pushing H.264 NAL units for 3 routes at 25fps.
* Executed on remote: `git reset --hard origin/rtmp-ffmpeg`
* Rebuilt C binary (no preview branch), rebuilt frontend (no LivePreview), rebuilt Elixir release.
* Deleted orphaned `preview_channel.ex` and `jmuxer.js` from remote.
* Remote is now clean at commit `326b397` (docs update).

## Key Decisions & System Constraints Resolved

### Why the live preview was CPU-expensive
The Base64 + JSON serialization + WebSocket push cycle per H.264 NAL unit is expensive on the BEAM:
- 3 routes × ~25 NAL units/sec = **75 encode+push operations/sec** on the BEAM
- Each operation: `Base.encode64/1` + `Jason.encode!/1` + Phoenix WebSocket frame assembly
- Result: 12-13% sustained BEAM CPU just for preview, even with no browser connected

### What would make it cheaper
A lower-overhead alternative would be:
1. **JPEG thumbnail at 2-4 fps** (already implemented as `/tmp/blackgate_preview_*.jpg`) — near-zero CPU
2. **HLS/fMP4 segment delivery** — GStreamer does the encoding and segmenting; Elixir just serves files
3. **WebRTC** — but requires STUN/TURN infrastructure
