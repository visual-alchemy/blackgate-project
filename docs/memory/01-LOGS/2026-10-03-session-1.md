## What Was Accomplished

### #3 — Telemetry correctness
- `native/src/gst_pipeline.c` `build_source_stats_json`: per-caller loop now also accumulates `packets-received/lost/dropped/retransmitted`; falls back to top-level only when the aggregate reads `<= 0` (listener sources reported top-level 0). Fixes `packets-received` always 0.
- `lib/blackgate/route_health.ex`: `0` is truthy in Elixir, so `packets-received || caller[...]` never fell back — changed to explicit `> 0` fallback for received/lost.
- `lib/blackgate/unix_sock_handler.ex`: added `{:tcp_passive, _port}` clause before the catch-all — stops the recurring `SocketHandler: Undefined msg type=:info ... <non-binary>` log flood.

### #2a — Source-side SRT error visibility (log-only)
- `gst_pipeline.c` bus WARNING now prints `Pipeline Warning from %s: %s [debug: %s]` and enriches `SOURCE_INVALID:<tag> <msg> [debug: <debug>]` with the Gst debug provenance. Verified live: `[debug: ../ext/srt/gstsrtobject.c(1640): gst_srt_object_read ...]`.
- **Reverted** the `srt_setloghandler(NULL, handler)` + `srt_setloglevel(LOG_WARNING)` attempt: libsrt invokes the handler during teardown and it SIGSEGV'd (exit 139, 3/3); it produced zero useful logs anyway. Removed → clean exit 0. The `Unknown or erroneous (0)` clobbered-last-error case therefore remains opaque (the real code is already present in the message in normal cases, e.g. `Connection timeout (16)`).
- No SRT-SRT / SRT-SDI behaviour change.

### #2b — Source-side reconnect ride-through (behaviour change)
- Native: any ERROR from `source`/`secondary_source` is now **recoverable** → prints `Recoverable source-gap error from %s: %s`, emits a `source_gap` JSON message, `break` (never `g_main_loop_quit` on a source blip).
- `lib/blackgate/route_handler.ex`: `@source_gap_grace_ms 15_000` + `source_gap_token` field. On `SOURCE_INVALID` **or** a `Recoverable source-gap error` line (non-dual-ingest, port open) it arms a 15s timer; on expiry, if `total-bytes-received` advanced → cancel + re-arm watchdog, else `trigger_restart`. Stale token ignored.
- `lib/blackgate/unix_sock_handler.ex`: explicit `source_gap` clause in both JSON handlers so it is not stored as stats.
- Wedge-proof invariant: every state always has a timer (grace/watchdog/reconnect); failover (dual-ingest) excluded so a secondary still wins; permanent silence falls back to the 60s watchdog.

## Key Decisions & System Constraints Resolved

- #2a kept log-only; `srt_setloghandler` is unsafe (teardown SIGSEGV) and must not be reintroduced.
- #2b reconciliation is **native never-quit + Elixir bounded give-up** (15s byte-liveness grace), preserving failover priority.
- Reconnect timing: gap ≤15s and logged → no restart; logged gap >15s → ~15s hold + 10s reconnect (~25s); silent stall → 60s watchdog + 10s (~70s).
- OMO agent/category routing moved to the ORION provider (`~/.omo/omo.jsonc` → `orion/vidioai-*`, same underlying models) — outside the repo; requires an opencode restart.
- SDI output capacity is a hardware count (≤8), not a routing choice; a device cannot be shared by two routes.
