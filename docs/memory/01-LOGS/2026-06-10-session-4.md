# Session Log: 2026-06-10 - Session 4

## Sprint Goal & Focus
Diagnose and resolve the physical SDI playout stuttering and audio drops on BWF Courts 1–4.

## What Was Accomplished

### 1. Root Cause Analysis
* **Analyzed** system logs and found `decklinkvideosink` reporting `Failed to schedule frame: 0xffffffff80000008` (invalid argument).
* **Identified** that the previous configuration of `do-timestamp=TRUE` on the GStreamer source element was overwriting the MPEG-TS packet timestamps with their network arrival times.
* **Discovered** that for remote internet-delivered RTMP feeds (BWF Courts 1–4), arrival jitter corrupted `tsdemux`'s internal PCR/PTS recovery. This resulted in highly jittery, out-of-order, or backwards-jumping timestamps being sent to the DeckLink audio and video sinks, causing hardware playout failures.
* **Confirmed** that local feeds (NTV and Magna TV) were unaffected because they run over a local network with zero arrival jitter.

### 2. Resolution
* **Modified** [gst_pipeline.c](file:///Users/eldyreynanda/Developer/Antigravity/blackgate-project/native/src/gst_pipeline.c) to set `do-timestamp=FALSE` on the source element. This ensures that `tsdemux` relies entirely on the stream's native PCR/PTS presentation timestamps generated by the encoder.
* **Transferred** the updated file to the gateway `192.168.40.61`, recompiled the native C engine, and hot-swapped the `blackgate_pipeline` binary in the production release path.
* **Restarted** the BWF Court routes (Courts 1–4) via RPC.

### 3. Playout Verification
* **Monitored** the route stats registry over a sustained period.
* **Verified** that all 4 courts initialized cleanly and are playing at exactly `25.0` fps with healthy, active audio buffers and non-zero RMS values:
  * **Court 1:** `audio_rms` = ~0.0584, `video_frames` advancing steadily at 25 fps, new `dropped_frames` = 0.
  * **Court 2:** `audio_rms` = ~0.0353, `video_frames` advancing steadily at 25 fps, new `dropped_frames` = 0.
  * **Court 3:** `audio_rms` = ~0.0256, `video_frames` advancing steadily at 25 fps, new `dropped_frames` = 0.
  * **Court 4:** `audio_rms` = ~0.0441, `video_frames` advancing steadily at 25 fps, new `dropped_frames` = 0.

## Key Decisions & System Constraints Resolved
* **Preserving Native Timestamps:** Verified that letting `tsdemux` manage timestamps using the stream's internal PCR clock is critical for remote RTMP feeds. Overriding timestamps with arrival times using `do-timestamp=TRUE` must not be used.
