Pure passthrough routes (UDP/SRT) remain untouched (`do-timestamp=FALSE`).
* **Jitter Margin Increase:** Updated `add_sink_to_pipeline` in `gst_pipeline.c` to set `max-lateness` to `200000000` nanoseconds (200ms) on `decklinkaudiosink` to absorb transient network delays.

### 4. BWF Courts 1–4: 8-Channel Audio Upmix (`gst_pipeline.c`)

**Root Cause:** BWF Court RTMP sources carry stereo (2-channel) audio. The gateway was outputting 2-channel SDI frames. The downstream SDI switchers for Courts 1–3 require **8 embedded audio channels** in the SDI frame — with only 2, they output silence on their monitored channel pair. Court 4 happened to work because its switcher input was configured differently.

**Fix:** Inserted `audiomixmatrix` into the SDI audio chain in `add_sink_to_pipeline` (`native/src/gst_pipeline.c`):
```
aqueue → audioconvert → audiomixmatrix(2ch→8ch, first-channels mode)
       → audioresample → audiorate → capsfilter(channels=8) → decklinkaudiosink
```
- Mode: `first-channels` — ch1→ch1, ch2→ch2, remaining 6 channels filled with silence.
- `acaps` capsfilter changed from `channels=2` to `channels=8`.

**Segfault debugged:** First attempt used `gst_util_set_object_arg(..., "matrix", "<<...>>")` with a literal GstValueArray string — this caused SIGSEGV (exit code 139) on the gateway's GStreamer. Switched to `mode=first-channels` which is equivalent and crash-free.

**Deployment:** C binary compiled locally + on gateway, hot-swapped into release. All 4 BWF Court routes restarted via Elixir RPC. Magna TV and NTV untouched.

**Verified:** All 6 routes running with active audio buffers and zero drops.

### 5. NTV SDI Audio Desync Mid-Broadcast (`route_handler.ex`)

**Root Cause:** NTV (an RTMP source via ffmpeg sidecar) had a 7-second audio gap at 22:12. GStreamer recovered (`SDI_AUDIO_RECOVERED`) but the physical DeckLink audio embedder on Device 4 lost sync and stayed silent. GStreamer reported buffers still counting — no alarm triggered. Required manual diagnosis and route restart to recover.

**Why it only affects RTMP:** RTMP → ffmpeg sidecar → SRT loopback → GStreamer has extra hops where brief hiccups occur. SRT sources go directly into GStreamer with no intermediate hop; the SRT protocol handles packet loss natively, so the DeckLink embedder never loses sync.

### 6. SDI Audio Desync Auto-Recovery (`route_handler.ex`)

**Implementation:** Extended `Blackgate.RouteHandler` (Elixir `gen_statem`) to parse `SDI_AUDIO_SILENT` messages from C pipeline stdout and automatically restart the pipeline when appropriate.

**New state field:** `sdi_audio_last_restart_at` — monotonic timestamp of last SDI-audio-triggered restart, used for cooldown enforcement.

**New constants:**
- `@sdi_audio_min_buffers_before_restart 5_000` — skip restart if source never had audio
- `@sdi_audio_restart_cooldown_ms 300_000` — 5-minute cooldown between auto-restarts

**Decision logic (in `maybe_restart_for_audio_desync/3`):**
1. `schema == "SRT"` → skip entirely (SRT is rock solid, untouched)
2. `total_buffers < 5000` → source has no audio → log `sdi_audio_source_silent` warning, no restart
3. Within 5-min cooldown → log `sdi_audio_desync_repeated` critical event, no restart
4. All clear (RTMP/HTTP/HLS + had audio + outside cooldown) → auto-restart pipeline, set cooldown

**Mechanism:** `maybe_restart_for_audio_desync/3` uses `send(self(), :sdi_audio_desync_restart)` to defer the state transition, then a dedicated `handle_event(:info, :sdi_audio_desync_restart, :started, data)` clause calls `trigger_restart/1`. This keeps the gen_statem data-update return (`{:keep_state, new_data}`) separate from the state transition.

**Deployment:** `mix compile` locally + on gateway. `.beam` hot-swapped into release ebin. Module hot-loaded into running VM via `:code.load_file`. Magna TV + NTV restarted via RPC to reinitialize gen_statem `data` struct with new field.

**Verified:** Both routes confirmed `started` with new PIDs at 22:48.
