# Session Log: 2026-05-30 - Session 2

## Sprint Goal & Focus
Implement Option 2 (Live Video Frame-Drop Monitoring) and Option 3 (Automated DeckLink Driver/Hardware Health Check) to prevent infinite reconnect crash loops during hardware/driver failure and detect CPU decoding bottlenecks.

## What Was Accomplished
- **GStreamer C Engine (Option 2)**: Added global tracking for `vrate` elements, queried their cumulative dropped and duplicated frames, and serialized them as `sdi_video_stats` in the JSON telemetry socket.
- **Elixir Stats Registry (Option 2)**: Updated `RouteStatsRegistry` to fetch the previous stats from ETS, calculate real-time deltas, and attach `drops_per_sec` and `duplicates_per_sec` fields to the telemetry.
- **Health Engine (Option 2)**: Configured `RouteHealth` to degrade route health status to `"warning"` if any SDI device's frame-drop rate exceeds `2.0` frames/second.
- **Circuit Breaker & Diagnostics (Option 3)**:
  - Tracked `consecutive_startup_crashes` in `RouteHandler`'s state data.
  - Suspends automatic reconnects after 3 consecutive startup crashes (circuit breaker).
  - Implemented automated diagnostics executing `System.cmd` checks against the GStreamer DeckLink registry, the `DesktopVideoHelper` daemon, and the `/dev/blackmagic/io*` files.
  - Updates the route status to `"error"`, saves the diagnostic message in Khepri under `"error_message"`, and stops the state machine to prevent CPU lockups.
- **React Frontend (Options 2 & 3)**:
  - Renders a red "Hardware Error" status dot and displays the custom diagnostic error message in the hover tooltip when in an error state.
  - Displays a detailed red alert banner showing the precise diagnostic message on the route details page.
  - Renders a new **"SDI Playout Statistics"** table showing active SDI device numbers, cumulative drops, drops/sec rate, cumulative duplicates, and duplicates/sec.
- **Verification**: Verified that all backend Elixir files, native C engine, and React frontend compile and build successfully with zero errors.

## Key Decisions & System Constraints Resolved
- **CPU Decoding Bottleneck**: Since this gateway operates without a dedicated GPU due to PCIe limitations, software decoding is the primary resource constraint. Adding frame-drop rate monitoring allows users to detect CPU load issues before they cause visible playout stuttering.
- **Self-Healing and Crash Prevention**: Rather than spinning CPU and flooding logs indefinitely when the DeckLink driver helper fails, the circuit breaker halts reconnect loops and saves local driver/OS diagnostics in Khepri for operator action.
