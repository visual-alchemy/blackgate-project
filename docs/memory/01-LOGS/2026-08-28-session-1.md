## Key Decisions & System Constraints Resolved

1. **In-process selector flip is only safe for same-PID-layout feeds.**
   Flipping between different-muxer feeds (our .152/.42 SRS relays) churns the
   SDI branch's tsdemux/decodebin pads → permanent freeze, even switching back.
   Same-layout feeds (same encoder config) tolerate the flip: instant switch +
   ~1-2s macroblock artifacts until the new feed's next IDR.
2. **SDI routes = kill/respawn switching (4s clean black), by design.**
   Broadcast judgment: clean black > macroblock garbage on air. A runtime
   PAT/PMT compatibility gate was considered and deferred — its payoff is
   artifacts on program SDI, which is worse than the black it replaces.
3. **OBS fast stop/start needs ~15s before reconnect** — expected, not a bug:
   SRT dead-peer window (~5s, abrupt kill sends no close handshake) + OBS
   exponential reconnect backoff (2→4→8→16s). Levers are OBS-side (reconnect
   delay, graceful stop), not Blackgate.
4. Never send flush_start/stop to an input-selector's src pad from outside.
5. DeckLink audio sinks pace by hardware clock even with `sync=FALSE` — branch
   queues never drain on demand; `leaky=downstream` dissolves backpressure but
   doesn't make teardown safe (context for the dormant machinery).
6. `journald` rate-limits under GST_DEBUG=6 firehoses — heavy debug env drops
   journal lines silently; use targeted categories and remove after capture.
