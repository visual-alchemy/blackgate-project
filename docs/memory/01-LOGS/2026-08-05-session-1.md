# Session Log: 2026-08-05 (Session 1)

## Sprint Goal & Focus
Diagnose route `ATP Line 5` (`12015`) on Primary Gateway (`192.168.40.61`) and analyze why real ATP SRT caller connections differ from local test pushes.

## What Was Accomplished & Key Findings

1. **Read-Only Primary Gateway Diagnostics (`192.168.40.61`)**:
   - Connected via read-only SSH (`192.168.40.61`) to check process state, UDP socket status, systemd logs, and ETS tables.
   - Identified that `blackgate_pipeline` process was missing after systemd restart at 21:23:42 until route was re-triggered (Stop -> Start).
   - Confirmed UDP port `12015` was open and listening (`users:(("blackgate_pipel",pid=119512,fd=19))`).

2. **Empirical Socket Test**:
   - Ran 3-second live Python UDP socket test on port `12015`.
   - Confirmed `TimeoutError`: zero UDP packets arrived during real ATP source test window.

3. **Critical Discovery (Friend Public IP Push vs Real ATP Source)**:
   - **Friend Public IP Push**: User's colleague pushed over Public IP WAN (`srt://publicip:12015?mode=caller&passphrase=...`) $\rightarrow$ **Blackgate received it successfully**! (Proves Mikrotik NAT, public IP port 12015 forwarding, firewall, and Blackgate SRT socket listener work 100%).
   - **Real ATP Source Broadcast Hardware**: Real ATP broadcast hardware caller pushed to `srt://publicip:12015` $\rightarrow$ **Blackgate failed to receive / connect**.

## Root Cause Analysis & Resolution (Failover ON vs OFF)

- **Empirical Breakthrough**:
  - **Failover OFF**: Primary Gateway (`192.168.40.61`) ingested real ATP stream (`104.45.53.232:52878`) perfectly at **`21.67 Mb/s`**, outputting **`1080i50` SDI** with **`0 dropped frames`**.
  - **Failover ON**: Primary SRT listener port `12014` failed / dropped incoming caller handshakes.

- **Root Cause**:
  - In `native/src/gst_pipeline.c` (line 1832), `input-selector` was configured with `"sync-mode", 1` (`GST_INPUT_SELECTOR_SYNC_ACTIVE`).
  - When `secondary_source` (port 12017) is idle/unconnected, `SYNC_ACTIVE` mode **blocked primary pad 0 waiting for timestamp synchronization from secondary pad 1**.
  - This buffer block stalled `srtsrc` listener task, forcing SRT socket queue overflow and connection drop.

- **Applied Fix**:
  - Modified `native/src/gst_pipeline.c` to set `"sync-mode", 0` (`GST_INPUT_SELECTOR_SYNC_NONE`), ensuring `input-selector` never blocks primary SRT listener buffers when secondary is idle.
