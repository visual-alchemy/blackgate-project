## Root Cause Analysis & Next Steps Hypothesis

- **Hypothesis 1 — Passphrase Special Character URI Encoding in GStreamer**:
  - Passphrase contains `%` and `&` (`K5894^#%Hk6LkKAxmS&Z*a`).
  - In GStreamer `srtsrc`, passing unencoded `&` or `%` in `uri="srt://0.0.0.0:12015?passphrase=..."` causes GStreamer's URI parser to truncate the passphrase string at `&`.
  - When the real ATP source negotiates AES key with the truncated passphrase, SRT handshake fails with `Application-defined rejection reason` / socket reset.

- **Hypothesis 2 — `pbkeylen` & `streamid` Handshake Mismatch**:
  - Real ATP broadcast source enforces `pbkeylen=16` or `pbkeylen=32` and optional `streamid`.
  - Local test caller used standard default key length, masking the production handshake parameter mismatch.
