### 2. Green Macroblocking Diagnosis
- **Symptom:** Occasional green macroblocks visible on client player (OBS/VLC).
- **Diagnostics:**
  - Checked input loopback stats: `packets-received-lost` and `packets-received-dropped` are exactly **0**. Input link is perfectly clean.
  - Checked output SRT sink stats: `packets-sent-lost` is **5.8%** on Court 1 and **8.5%** on Court 2. Packet loss on output transmission is causing skipped slices/key frames.
- **Root Cause:** 
  - GStreamer's `srtsink` does not expose `rcvbuf` or `sndbuf` as element properties (only as URI parameters). Our codebase previously failed to append them to the SRT URI.
  - Fix has been pushed to append `sndbuf`, `rcvbuf`, `oheadbw`, and `maxbw` directly to the SRT URI query parameters.
  - **OS Level Limit:** Running `sysctl net.core.rmem_max net.core.wmem_max` on the remote gateway returned **`212992` (208 KB)**.
  - The small default OS UDP buffer limit caps SRT sockets at 208 KB, causing instant UDP socket overflows and packet drops under 9–14 Mbps bitrates.

### 4. Packet Alignment and PCR Smoothing (Implemented)
- **Problem:** GStreamer forwarded raw MPEG-TS buffers from loopback directly to SRT sink. Because of CPU scheduler latency, GStreamer read them in bursts and sent them at unlimited speed (up to 1 Gbps) on the LAN. This burstiness overflowed MediaKind RX1's network cards, causing packets to drop permanently and trigger green macroblocking during fast movement.
- **Solution:** Added `tsparse` element before `srtsink` in `gst_pipeline.c`. 
  - Configured `alignment` to `7` (forcing perfect 1316-byte UDP packets matching standard MTU).
  - Configured `set-timestamps` to `TRUE` to smooth out PCR clock jitter.
  - Limits sending rate and smooths delivery spacing to receiver card.

### 5. Non-Monotonic Timestamps and Decoder Synchronization (Implemented)
- **Problem:** Upstream RTMP source from cameras sends duplicate, out-of-order, or non-monotonic timestamps (DTS/PTS). While software players (OBS/VLC) silently recover, professional hardware decoders (MediaKind RX1) require strict, clean timelines. Direct pass-through (`-mpegts_copyts 1` in FFmpeg) caused severe decoder sync failure (continuous green macroblocks on the RX1).
- **Solution:** Changed `-mpegts_copyts` to `0` in `route_handler.ex` for the FFmpeg sidecar. This forces FFmpeg's `mpegts` muxer to ignore incoming broken timestamps and regenerate a perfect, linear, monotonic DTS/PTS timeline for the output stream.
