# 2026-09-01 — Session 2: Guarded Seamless SDI Failover

## Sprint Goal & Focus

Implement opt-in, keyframe-gated SDI source switching while retaining the proven restart fallback for incompatible MPEG-TS inputs.

## What Was Accomplished

- Added `seamless_sdi_failover` route configuration, validation, edit control, and route-detail strategy display.
- Required `failover_enabled=true` and `auto_join=true` when seamless mode is enabled.
- Passed seamless mode to native only for routes with an SDI destination.
- Kept both dual-SRT inputs warm and retained non-blocking selector synchronization settings.
- Added per-source PAT/PMT parsing and compatibility checks for transport stream ID, program, PMT/PCR/video PIDs, elementary stream PID/type layout, PMT descriptors, codec type, and codec-header signature.
- Added H.264 IDR, H.265 IRAP, and MPEG-2 I-picture gating before selector changes.
- Added native rejection messages and backend restart fallback on incompatible stream maps, missing metadata/keyframe timeout, or missing native acknowledgment.
- Preserved acknowledgment-gated active-source persistence.
- Updated `docs/seamless-sdi-failover-plan.md` with implementation status and remaining normalization work.
- Fixed stale empty route supervisors: when a transient RouteHandler exits normally, a later Start request now replaces the empty supervisor instead of returning false success.
- Added Phoenix parameter filtering for tokens, passwords, passphrases, secrets, and authorization values after live journal inspection confirmed WebSocket parameters were logged.
- Promoted sanitized native `Error:`, pipeline warning, and source-invalid output to production-visible log levels; this exposed a DeckLink `ScheduleVideoFrame` `E_FAIL` that had previously appeared only as a status-0 native Port exit.
- Traced `do-timestamp` history: the June 10 gateway hot-fix to preserve MPEG-TS timing was documented but never committed, and later full builds restored the repository's conditional `do-timestamp=true` behavior for SDI routes.
- Restored `do-timestamp=false` for every network source so `tsdemux` uses encoder PCR/PTS instead of SRT/UDP packet-arrival timing. Updated seamless timing documentation and added dual-input regression assertions.

## Key Decisions & System Constraints Resolved

- `sync-streams` remains disabled because prior deployed testing showed inactive-input synchronization can stall the active SRT listener when the peer is absent.
- Network sources preserve encoder PCR/PTS with `do-timestamp=false`; target codec-header and keyframe gating supplies the guarded media switch boundary without converting arrival jitter into timestamp jitter.
- Arbitrary incompatible muxes are not switched live. They deliberately fall back to restart rather than risk decoder freeze or corrupted program output.
