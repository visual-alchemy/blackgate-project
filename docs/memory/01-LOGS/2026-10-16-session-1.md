# 2026-10-16 Session 1 — Blackgate-Lite Port: Failover, Codec Stats, and Docker Proof

## Sprint Goal & Focus

Port the live deltas from `origin/blackgate-lite` (the C-engine product line) into
the Rust engine on `rust-migration`, then prove the port builds, tests, and runs
end-to-end under Docker on the linux/amd64 production target.

## What Was Accompanied

Ported four live behaviors out of `blackgate-lite` into `native/rust/`:

1. **`input-selector` sync-mode.** Rust shipped the archived C oracle's stale
   `sync-mode=1` ("clock"), which blocks the primary pad while waiting on an idle
   secondary and stalls the `srtsrc` listener into SRT socket overflow. Now
   `active-segment` (0), matching lite commit `8cca10e`. Enum confirmed via
   `gst-inspect-1.0`: `GstInputSelectorSyncMode { 0=active-segment, 1=clock }`.
2. **auto_join failover lifecycle.** Three defects fixed together:
   - `SelectorState::new` hardcoded `secondary_joined: true`, making
     `join-secondary` a silent no-op on `auto_join=false` routes.
   - `join_secondary` used `set_state(Playing)`, which does nothing on a locked
     element; now `set_locked_state(false)` + `sync_state_with_parent`.
   - The builder never locked the secondary, and a bare `set_state(Null)` also
     strips the lock, so the source could never be restored.
   - `switch_to` now runs lite's atomic lifecycle: join before switching to
     secondary, leave only after switching back to primary.
3. **Codec detail stats.** H.264/HEVC/MPEG2 parsers now emit
   `profile_idc`/`level_idc`/`chroma_format_idc`/`bit_depth`/`sar_*` and surface
   `video-codec`, `video-profile`, `video-level-idc`, `video-chroma-format`,
   `video-bit-depth`, `video-sar-num`/`-den`. HEVC also gained the
   conformance-window crop it was skipping, which had been reading the bit depths
   from the wrong offset. Name tables byte-match the C.
4. **`bytes-received`.** The oracle omitted this key; lite emits it; Elixir
   `route_controller.ex:31,41` reads it as the "is data flowing?" fallback. Rust
   emitted a `total-bytes-received`-only payload, so the fallback always read 0.
   Now emitted as a per-report delta on both source and sink paths.
5. **Persisted `active_source`.** `engine-config` parses it, the builder selects
   `sink_1` when Elixir reports `"secondary"`, and
   `route_handler.ex` now sends it in the init JSON (it tracked the field in
   state/DB but never transmitted it — the engine-side port would have been
   inert).

### Investigated and deliberately NOT ported

`blackgate-lite`'s keyframe-gated switch state machine (`pending_source_index`,
`complete_pending_switch_on_keyframe`, `reject_pending_switch_if_incompatible`,
`source_maps_compatible_unlocked`, ~150 lines) is **inert in lite itself**:
`pending_source_index` is declared `-1` and only ever checked or reset to `-1`,
never assigned a non-negative value. `switch_source()` switches immediately.
Porting it would have added dead code with a tests-pass illusion.
`ts_normalizer.c` (302 lines) is also dead in lite — no `#include`, zero `bg_ts_`
references; it is a duo2 leftover.
`video-pid` was parsed but read by nobody — skipped per YAGNI.

## Verification Performed

- `cargo fmt --all -- --check` — clean.
- `cargo clippy --workspace --all-targets -- -D warnings` — exit 0, no warnings.
- `cargo test --workspace --lib` — **31/31 pass** on linux/amd64.
- `python3 native/rust/scripts/ipc_smoke.py --engine native/build/blackgate-engine`
  — **"Rust IPC smoke passed"** (stdin init JSON → live srtsrc/udpsink →
  PLAYING → Unix-socket `route_id:` handshake → `stop-route` → `Socket closed.`).
- Docker image build (`--platform linux/amd64`) — exit 0, 1.05 GB.
- **Live E2E in container**: created and started real SRT routes through the API.
  Elixir spawned the Rust engine as an Erlang Port (PID 105, argv
  `blackgate-engine <route_id>`); engine reached PAUSED/PLAYING; SRT listener
  bound on UDP 9110 (verified by bind-refusal probe). Stats JSON on the wire
  carried the ported `bytes-received` key. `auto_join=false` route logged
  `secondary held at NULL`; switch→secondary emitted `SECONDARY_JOINED` then
  `SOURCE_SWITCHED:secondary`; switch→primary emitted `SECONDARY_LEFT` then
  `SOURCE_SWITCHED:primary`.

## Key Decisions & System Constraints Resolved

- The corrupted release build was **not** a port defect. A first run reported
  `engine-thumbnail::stop_wakes_sleeping_worker_within_shutdown_budget` failing
  with `Failed to find element factory with name 'decodebin'`. Root cause: the
  `builder` stage carries only GStreamer dev headers (4 plugins), not runtime
  plugins. A test overlay adding the runtime plugin set made it pass. Environment,
  not code.
- `config/runtime.exs:69` hardcodes `secret_key_base: nil` with the guard
  commented out at `:50-55`. **Corrected finding:** this does NOT prevent boot.
  The release boots, serves, and authenticates. Blackgate's auth is Bearer-token
  via Cachex (14-day TTL), not cookie sessions, so the nil signing key is latent
  rather than blocking. The earlier "prod release cannot boot" claim was wrong.
- The base `docker-compose.yml` publishes `9000-9500/udp` explicitly and uses
  bridge networking by design for Mac/Docker Desktop. `docker-compose.failover.yml`
  deliberately `!reset`s `network_mode: host` and `devices:` — it is a dev-laptop
  file, not a production one.
- Docker builds on this Mac require `--platform linux/amd64` emulation: the
  Dockerfile pins `node-v20.19.0-linux-x64.tar.xz` (`:33`) and
  `/usr/lib/x86_64-linux-gnu/gstreamer-1.0/` (`:83`, `:178`). Native arm64 build
  is not currently possible.
